The Capability Transformer

Four practical sheets for moving a ChatGPT use case from interesting to adopted, governed, and measurable.

Sheet 1 · Workflow intake card

Work to improveWhat recurring task, decision, handoff, or knowledge burden creates friction?
Current consequenceWhere do delay, rework, inconsistency, missed context, or avoidable effort appear?
Required inputsWhich sources, examples, tools, files, and context are needed?
Human authorityWhat judgment, approval, commitment, or escalation remains human?
Data boundaryWhat information is permitted, restricted, or prohibited?
Success measureHow will quality, time, rework, completeness, adoption, or economics change?
OwnerWho owns the workflow, the AI asset, the data, and the outcome?

Sheet 2 · Prompt/workflow assurance checklist

Purpose and user are explicit
Required context is identified
Approved sources are named
Output format is testable
Examples cover normal and edge cases
Uncertainty behavior is defined
Human checkpoint is visible
Restricted data is excluded
Escalation path is defined
Evaluation set exists
Owner and review date exist
Retirement criteria exist

Sheet 3 · Demo-to-adoption design

One work momentDemonstrate one consequential task, not a feature tour.
Before / afterShow the old work, the changed mechanism, and the retained human decision.
PracticeParticipants use their own bounded example before leaving.
Job aidProvide the prompt/workflow, source rule, checklist, and escalation path.
ReinforcementSchedule office hours, champion follow-up, and a review point.
MeasureTrack repeat use and the work outcome - not attendance alone.

Sheet 4 · Adoption and value scorecard

SignalQuestionEvidence

DepthAre people using more than basic chat?Tools, GPTs, Projects, apps, repeat patterns
